What changed?

Stripe's API versioning page lists the current version as 2026-07-29.dahlia. Stripe says major releases can include changes that are not backward-compatible, while monthly releases include only backward-compatible changes and use the same release name as the last major release.

Who is affected?

This matters for teams changing an account default API version, setting Stripe-Version per request, upgrading Stripe SDKs, or creating webhook endpoints with a specific API version.

What can break?

  • SDK types can stop matching the API version an integration actually uses.
  • Webhook event payloads can differ from request/response payloads if endpoint versions are not aligned.
  • Older SDK versions may use account defaults while newer SDKs may align with the API version current when the SDK was released.

Smallest safe migration

  1. Record your account default API version, SDK version, and webhook endpoint API version.
  2. Identify whether you are moving across a major release or only to a monthly release.
  3. Pin or override versions intentionally in code where needed.
  4. Test request/response handling, webhook event parsing, TypeScript types, refunds, disputes, and Connect flows before production.
