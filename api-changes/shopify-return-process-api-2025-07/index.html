Shopify Returns API: returnProcess, returnRefund deprecation, and 2025-07 migration

Reviewed August 24, 2026Evidence confidence: Official Shopify developer changelog and docsPrimary domain: Returns / refunds / exchanges
Current decisionApps that create returns, approve return requests, process refunds, manage exchanges, or calculate return financial outcomes should migrate to the Shopify Returns API flow built around returnProcess and Return.suggestedFinancialOutcome.

What changed?

Shopify's Admin GraphQL API 2025-07 officially launched return processing APIs. The returnRefund mutation is deprecated and replaced by returnProcess. The Return.suggestedReturnRefund field is deprecated in favor of Return.suggestedFinancialOutcome.

The practical change is that returns, refunds, exchanges, item disposition, and financial processing are now intended to move through one explicit return-processing step instead of older separate return-refund flows.

Who is affected?

This affects Shopify apps and integrations that use the Admin GraphQL API for return management, including apps that:

  • Create returns with returnCreate.
  • Approve return requests with returnApproveRequest.
  • Issue return refunds through returnRefund or older refund flows.
  • Use Return.suggestedReturnRefund or Return.suggestedRefund to calculate what should happen financially.
  • Coordinate exchanges, restocking, disposal, refund shipping, refund duties, or return-line-item financial transfers.

What can break?

  • Deprecated mutation risk: apps that keep building around returnRefund are building on a deprecated return-refund path.
  • Financial outcome mismatch: refund and exchange logic can drift if the app still reads old suggested-refund fields instead of suggestedFinancialOutcome.
  • Exchange handling errors: fulfillment orders for exchange items depend on the return-processing flow.
  • Partial-return complexity: refunds, duties, shipping refunds, item disposition, and exchange items may need to be tested together, not as isolated refund calls.

Smallest safe migration

  1. Inventory every Shopify Returns API call. Search your codebase for returnCreate, returnApproveRequest, returnRefund, refundCreate, suggestedReturnRefund, and suggestedRefund.
  2. Map old flows to return processing. Identify which flows should now use returnProcess and Return.suggestedFinancialOutcome.
  3. Test refund and exchange cases together. Include full refund, partial refund, exchange, refund shipping, refund duties, restock, disposal, and failed payment/refund paths.
  4. Check scopes and permissions. Confirm the app has the return and refund permissions needed for the migrated flow.
  5. Upgrade by API version deliberately. Test the migration against the Admin GraphQL API version you intend to use before changing production return handling.
